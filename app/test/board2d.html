Highlight precedence / overlap (one glyph per square)

board-interface.js: error > success > select > hint > move. A square lit by several kinds at once must render exactly one glyph -- the highest-precedence kind's fill+glyph together, never a mix or a stack. Membership is tracked per kind (highlight(squares, kind) REPLACES that kind's whole square list), so this setup makes one highlight() call per kind listing every square that kind should cover, rather than one call per square -- calling highlight() square-by-square for the same kind would just overwrite itself.

Matrix: b5 move+hint (expect hint) · c5 move+hint (expect hint) · f5 move+hint+select (expect select) · e5 move+hint+select+success (expect success) · d5 all five incl. error (expect error). After clearing hint: b5 and c5 fall back to move; f5/e5/d5 unaffected.
